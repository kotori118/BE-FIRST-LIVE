# 本体接続の監査記録（2026-11-11）

正本: Google Drive設計書v0.26と末尾の起動時更新指定。既存White Aqua GlassのReact画面と共通モデルを移行ブランチから再利用。ユーザー確定仕様の再選択は行っていません。

## 実装済み

- 同一のEntryEditor・カード・ナビ・色指定を共用。HOMEはライブ数/聴いた曲、MY LIVEは履歴先頭。ツアー・検索・絞込状態を画面遷移中保持。
- U:/L:のSongRef、stable entry ID、基本セトリと公演差分、披露事実を分離。通常FULL、メドレーSHORT/解除FULL、手動null除外。
- 未入力セトリを披露率の分母から除外。同曲複数披露と披露公演数を区別。カバーも聴いた曲へ含め、未聴はBE:FIRSTのみ。
- Firebase本人限定、直接Firestore保存、全体revisionとentity revision、トランザクションで競合拒否。旧Cloud Functions依存を除去。
- 既存の同期要求処理をsync-request.jsへ一本化。ソース読取・検証・差分計算はGASのみ。移行時にあった別の未使用ブラウザー用同期実装は除去。
- 復元はステージング・再読込一致検証・activeポインター切替。直前データを保持して戻せる。
- 起動時は前回Firestore値を先に表示して操作可能にし、同期完了後に最新へ更新。失敗時は前回値保持。
- 試験データの操作はメモリ内のみ。歴代公演・参戦履歴の初期投入は未実施。

## 検証

- Firestore/GAS/起動処理: 21テスト通過。本人/他人/匿名、原子的な同期、失敗時保持、空・不正データ、期限付き要求、本体bootstrap、revision必須の保存、未完成ステージへの切替拒否、復元切替を確認。
- 本体のドメイン: 10テスト通過。SHORT/FULL/null、メドレー、テンプレート差分と衝突、昼夜重複判定、JSON roundtrip、参照統合、カバー/未聴、明示確認用統合候補、Firestore読戻しのキー順差とセトリ順序の照合。
- TypeScriptと本番ビルド通過。
- ブラウザー試験表示: LIVEツアー展開、3/3の参加チェック、HOMEが1公演29曲へ変化、公演詳細29曲、ランキング/披露率が表示されることを確認。
- 実Firebaseルール反映後のiPhone/PC間保存、実プロジェクトの復元、スマホ実機の見た目はユーザー環境で確認が必要。

## Phase 1の残件（確定仕様を削除したものではない）

- 楽曲詳細の披露履歴・曲別編集画面、作品情報のUniverse既存情報からの取込と補完UI。
- 公演比較の詳細表示、レア曲の専用画面の仕上げ。
- 公演削除時の影響対象・件数プレビュー。現段階は公演削除を提供せず、保存層でも削除を拒否。
- 競合時のデータ単位で保存する側を選ぶ体験の仕上げ（現状は競合検知・再読込/編集選択、無条件上書き不可）。
- CSV閲覧書き出し、復元プレビューの全対象詳細、実Firebaseでの復元・ロールバック受入。
- 試験ツアーの残り3公演のセトリ、メドレー/SHORT/初披露フラグの照合。入力不足をコピーで補わない。
- 全歴代公演・作品・セトリ・参戦候補の整理と、本人承認後の一括初期登録。

予想・バックテストは基本機能完成後。今回をPhase 1の全件受入完了として扱いません。
